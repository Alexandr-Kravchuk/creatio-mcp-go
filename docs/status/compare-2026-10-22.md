# Side-by-side read run and process footprint (2026-10-22)

Date: 2026-10-22, with a footprint re-check on 2026-10-23. Reference: clio 8.1.0.142 (`clio.dll`, `mcp-server`).
This server: built from `main` at `e45af4d` (v0.2.0 plus the installer and Homebrew docs, before the v0.2.1 fixes).
Stand: the disposable on-premises stand of the T23 write run. Machine: macOS arm64, .NET 10.

This report records the figures the [comparison deck](../clio-mcp-comparison.md) cites; until now they existed only
in a session report.

## Read run

`scripts/compare-mcp.py --clio-dll <clio 8.1.0.142 clio.dll> --go-bin <binary> --cases scripts/mcp-parity-cases.json
scripts/parity-cases/*.json --evidence evidence/compare-2026-10-22/read-live.json`. The harness calls clio first in
every case, so the second server may meet a stand that the first call has already warmed.

Evidence: [`evidence/compare-2026-10-22/read-live.json`](../../evidence/compare-2026-10-22/read-live.json) (verdicts,
timings and differing JSON paths only).

| Verdict | Cases |
|---|---:|
| match | 823 |
| known-diff | 41 |
| both-failed | 17 |
| mismatch | 2 |
| error-text | 0 |
| **total** | **883** |

The two mismatches:

- `list-user-tasks default`: clio's execution log has 25 lines, this server's 24. The missing line is clio's
  `Reading user task catalog from '<env>'...`; this server writes it since v0.2.1 (`5cb5841`).
- `list-pages search`: `$.pages[0].packagename` differs. A repeated `list-pages` search by hand returned the same
  first three pages on both servers; the stand returns pages with equal sort keys in varying order.

The first attempt of this run went out while the stand's host did not resolve and is not counted. It showed that
`get-sys-setting` reported "Authentication error" for an unreachable host; fixed in v0.2.1 (`db8ab4a`).

Timings, seconds (`clio_seconds` / `go_seconds` of the evidence):

Process start in the harness: clio 3.91 s, this server 0.06 s.

The largest per-tool sums (match and known-diff cases) show where the time goes: `list-apps` clio 38.06 s / Go 0.39 s

`get-page` 35.16 / 25.51 (n=8), `get-page-hierarchy` 22.89 / 16.56 (n=10).

### Heavy reads with the order alternated

By hand after the run, not in the evidence: each tool called 4 times on each server, Go first in calls 1 and 3, clio
first in calls 2 and 4. "Median" is the median of calls 2–4; the first call is listed apart.

| Tool | clio first call | clio median | Go first call | Go median |
|---|---:|---:|---:|---:|
| `list-pages` | 5.16 | 4.74 | 0.10 | 0.14 |
| `list-apps` | 0.63 | 0.30 | 0.28 | 0.03 |
| `get-page` | 4.38 | 2.64 | 2.33 | 2.35 |
| `get-page-hierarchy` | 2.38 | 1.93 | 1.71 | 1.82 |
| `find-entity-schema` | 0.11 | 0.05 | 0.06 | 0.05 |

Where the stand does the work (`get-page`, `get-page-hierarchy`) the medians differ by 6–11%. The large differences
are in time clio spends on itself: process start, the first call, `list-pages`, `list-apps`, `compile-status`.
Not re-measured since: the stand is no longer used for timing.

## Process footprint

Each server started three times through `scripts/clio-inventory.py`'s `InventoryServer`, without a stand: time to the
answered `initialize`, resident memory (`ps -o rss`) after start and after the calls, 20 `list-environments` calls
(median of calls 2–20), one `get-tool-contract` for three tools. Ranges over the three starts.

| | clio 2026-10-22 | clio 2026-10-23 | Go 2026-10-22 | Go 2026-10-23 |
|---|---|---|---|---|
| Start to answered `initialize` | 3.18–3.94 s | 1.84–4.74 s | 0.04–0.06 s | 0.06–0.72 s ᵃ |
| Resident memory | 136–170 MB | 129–140 MB | 24–28 MB | 24–29 MB |
| `list-environments`, median | 5.4–6.6 ms | 3.8–7.6 ms | 0.7–1.0 ms | 0.8–3.2 ms |
| `get-tool-contract`, 3 tools | 145–157 ms | 92–187 ms | 1–2 ms | 2–3 ms |

ᵃ 0.72 s was the first start of the freshly built file; the next two took 0.06–0.07 s.

On disk (`du -sh`): the clio 8.1.0.142 tool store is 504 MB and needs the .NET 10 runtime besides; this server is one
23 MB file. The release archives of v0.2.1 are 6.3–7.3 MB.

The 2026-10-23 column used the v0.2.1 source (`df4198a`) and the same `clio.dll`.
